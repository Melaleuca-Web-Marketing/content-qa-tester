# Melaleuca Content Testing Tools (browser extension)

Companion to the Content QA Tester. Lives in `extensions/content-testing-extension/`.
Load: chrome://extensions -> Developer mode -> Load unpacked -> pick this folder.

## Popup tabs
- **Tools**: the preview tools and Culture Links (below).
- **QA Tests**: starts Content QA Tester runs for the open tab (see *QA Tests* below).

## Tools

### Culture Links
- Red glow + label: link goes to a different culture than the page (e.g. ie link on pl site).
- Orange dashed: stage page links to a production host (right culture, wrong environment).
- Bottom-right badge shows the count; click it to jump through offenders.
- Hover a flagged link to see the full URL in the tooltip.

Hosts understood: `www.melaleuca.com` (US), `xx.melaleuca.com` and `productstore2-xx-preview.melaleuca.com`.
GB and UK are treated as the same culture. Edit ALIASES / parseHost in content.js if the UK
site uses a different code.

### Category Banner, Hero Slide and Mix-In Ad Preview
Replaces the "Category Banner Live Preview" VS Code extension. Three tools, opened from separate cards in
the popup, each in its own tab:

- **Category Banner Preview** (green, `banner-preview/index.html`): the full-width banner at the top of a
  category page.
- **Mix-In Ad Preview** (violet, `banner-preview/index.html?tool=mixin`): the ad card inside the product
  grid. It's rendered as the first card of the real grid, beside product cards: 2 per row, 3 from 992px,
  4 from 1210px, with the filter menu from 768px. The card is at most 230px wide (about 145px at 320 and
  190px at 415) and at least 450px tall, and stretches to its row. The tile header shows the ad's size.
  The background is anchored top-left (crops right/bottom); the mobile image is optional, and without one
  the desktop image is used at every width. "Show product cards beside the ad" turns the neighbors off.

- **Hero Slide Preview** (orange, `banner-preview/index.html?tool=hero`): a home page carousel slide
  (`m-fwBanner -h-lg -slide -stackMobile`) rendered inside the real `.o-heroCarousel`, so the arrows and the
  dots/pause pill sit exactly where they do live. Height defaults to `-h-lg` (380px; `-h-md`, `-h-sm-md`,
  `-h-sm` available). The button is generated by the CMS outside your HTML, so it's set under
  *Slide & button*: color (`bg-green`, `bg-dark`, `bg-white`, …), link, and text per language (text
  expansion applies to it too). Checks added for slides:
  - the button off-center from the copy (it centers on the copy column, so padding/margins on the copy
    move the text but not the button), with the copy and button centers drawn;
  - copy or the button under the arrows or dots (shown as purple dashed zones);
  - white copy on the white area below the image on phones (`-stackMobile` stacks the copy under a
    210px image below 768px; use `md:text-white`);
  - the slide growing past its height (768px and up; on phones it stacks and grows by design);
  - **extra margin on the button** (sometimes added in Optimizely to nudge the copy away from objects in
    the image). Import from tab keeps the button's exact classes and inline styles, so the preview matches
    the live slide; anything beyond the standard CMS button (e.g. `md:ml-60`, `style="margin-top: 8px"`)
    is listed read-only under *Slide & button* with a *Remove extras* button. It can't be added or edited
    in the tool. Each tile measures the margin from the live CSS at its width (so `md:` classes only count
    from 768px), shows it in the header (`button margin ←60px`) and hatches it next to the button. This
    also works for a whole slide pasted from the site.

They share the same engine and features (below) but keep **separate saved items, settings and custom
templates**, and look different so they aren't confused. Pasting another tool's markup (a whole
`m-fwBanner -slide` in Category Banner Preview, a `m-mixinAd` in Hero Slide Preview, …) shows a warning
with a button that moves the item to the right tool. Import from tab only picks up that tool's kind
(hero slides from the home page carousel, skipping Slick's cloned slides, including the button's text,
color and link), and export files are marked with their tool so they can only be imported into it.

Features (both tools):

- **Copy**: paste the banner HTML, either the contents of `.m-rte` or the whole `<a class="m-fwBanner">`
  copied from the site. Every viewport updates as you type (no reloads). One tab per language;
  the first language is the reference. The editor is a code editor (CodeMirror):
  - Syntax colors, line numbers, wrapping, auto-closing tags, folding, Ctrl+F search, undo per language.
  - **Class suggestions** inside `class="…"`, read from the live app.css: CSS value next to each, color
    swatches, and breakpoint/state prefixes (type `md:` to see only classes that exist at that breakpoint).
    Ctrl+Space opens them. Hover any class to see its CSS and the breakpoint it applies at.
  - Classes that aren't in app.css are underlined, with "did you mean" fixes (`pl-65` → `pl-64`, `pl-60`, `pl-70`).
  - **Right-click a class** for its scale: every class that sets the same property at the same breakpoint,
    sorted by value (`pl-18 · pl-20 · pl-24…`, `md:text-2xl 24px · md:text-2xl-2 28px · md:text-3xl 30px`,
    font weight, line height, letter spacing, negative margins; colors show swatches). Hover a value to
    preview it in every viewport, click to keep it (one undo step), Esc or click away to put the original
    back. **Ctrl+Alt+↑/↓** steps the class under the cursor to the next larger/smaller value.
  - Unclosed / stray tags are underlined in red.
  - **Format** (Shift+Alt+F) indents the HTML without changing how it renders: inline text and
    `span`/`strong`/`a` runs keep their exact spacing.
  - **Classes…** opens a reference: the brand color palette (every `text-`/`bg-`/`border-` class per color),
    typography, spacing, sizing, layout and components, filterable by breakpoint. Click to insert at the cursor.
- **Viewports**: the site's Tailwind breakpoints: XXS 320, XS 415, SM 576, MD 768, LG 992, XL 1210.
  Jump to one with the buttons under the toolbar (each has a status dot) or **Alt+1…9** in order
  (Alt+0 = Free width); the button for the viewport at the top of the preview is highlighted.
  *Breakpoint edges* adds 414/575/767/991/1023/1209; *Free width* is a tile you can drag to any width.
  Edit the list under Settings.
- **Background images**: desktop (≥1024), tablet/medium (576–1023), mobile/small (≤575). Drop a file,
  click to browse, or paste an https URL. Pasted full banners use their own images unless you set one.
- **Keep-out zones**: drag over the products/faces in each image. The image crops differently at every
  width (object-fit: cover), and zones follow it; any line of copy that touches a zone is flagged red.
  The editor also shows what part of the image is visible at the narrowest/widest width.
- **Center copy** (per image: horizontally, vertically or both): measures the empty space the copy sits in,
  from the banner edges to the nearest keep-out zone (where the objects begin), and draws the gaps on each
  side in px, plus a readout in the tile header. Green = balanced; amber = off by more than the tolerance
  (Settings, default 6px). It's a visual aid only (no warnings). For a different space, draw a *Copy area*
  in the zone editor.
- **Checks** under each tile: copy overlapping a zone, copy running outside the banner or a clipping box,
  horizontal scroll, banner taller than its set height, broken images, missing images.
- **Text expansion**: lengthen the copy (+15–100%, or *Smart*, which grows short strings more, like real
  translations) and add *Accents* (Ä É Š ą ł) to judge localized copy before you have it.
- **Check all languages**: renders every language at every viewport and shows a pass/fail grid;
  click a cell to jump to it. **Compare languages** shows all languages side by side at one width.
- **Snippet lint**: unclosed tags, images without alt, http:// images, English (`--enus`) assets left in
  another language, copy identical to the reference language.
- **Layout grid**: *Grid* in the toolbar draws translucent columns over every banner/slide/ad; the ⚙
  button sets columns per screen size (phone <768 / tablet / desktop ≥1024; default 4/8/12, and 4 at every
  size for mix-in ads), gutter, outer margin, optional baseline rows, and whether it fits the whole banner
  or its content area (the copy container inside its padding, e.g. the 120/170px on hero slides). Each
  tile's header shows the column width at that viewport (`grid 12 × 30px`).
- **Design overlays**: add the XD export or paste a screenshot (Ctrl+V). It's sized to the banner box
  (fit width / fit height / stretch / actual pixels) and shown on the viewport you pick, or on every
  viewport that uses the desktop, tablet or mobile image. Compare with *Overlay* (opacity, *Difference*),
  *Swipe* (hover across the tile) or *Below* (design under the build). Turn on *Move* to drag it into
  place; arrow keys nudge 1px (Shift = 10px). X/Y/Scale fields fine-tune it.
- **Banners**: each banner (copy, images, zones, designs) is saved in the browser. Use *Duplicate* for next
  month's version, *Export*/*Import file* to share a `.banner.json` with teammates, and
  *Import from tab…* (or **Import banner from this tab** in the popup) to pull a banner off a live or
  stage melaleuca.com page, as a new banner or as another language of the current one.
- **Templates**: Category banner (with height/width/alignment options matching the `m-fwBanner` modifiers),
  Mix-in ad, or your own page-context HTML (same `@@BANNER_SNIPPET@@` tokens as the VS Code extension).

Styles come from the live `app.css` and the brand font kits (editable under Settings), so the preview
matches production. Scripts in snippets don't run (extension pages block inline scripts).

#### Editor bundle
Chrome extensions can't load code from a CDN, so CodeMirror is bundled into
`banner-preview/vendor/codemirror.js`. Source and pinned versions are in `extensions/banner-editor-src/`;
to update: `cd extensions/banner-editor-src && npm install && npm run build`.

### QA Tests (popup tab)
Quick access to the Content QA Tester (production by default: `https://usifhqpsagqat01.melaleuca.net`;
change it under *QA Tester server*, e.g. to a local instance, which Chrome asks permission for).

- **Uses your QA Tester session.** Requests carry the browser's `tester_sid` cookie, so tests started here
  appear in the same queue, Job History and reports as the web app.
- **Reads the open tab** (`qa/context.js`):
  - Environment and region come from the host (production, `productstore2-xx-preview` stage, `productstore2-uatxx` UAT).
  - Culture comes from `sc_lang` or the page language.
  - The category is matched against the QA Tester's own category list (`/api/config`).
  - It also detects what's on the page: category banner, mix-in ads, hero carousel, and SKUs (from the
    product page's "Item: 60202" line, structured data or `data-sku`).
- **Suggests the tests that fit:**
  - category page with a banner → Category banner (+ Mix-in ads when there are some; Sort order available)
  - product page → SKU (+ PDP)
  - store home → Store home (PSLP)
  - anything else → Page
  Unavailable tests are shown greyed out with the reason.
- **Options:** widths, test name, and *Run signed in*. Username and password are asked for only when a selected
  test needs them (PSLP and PDP always do). The password is sent with that run and never stored; the username
  is remembered per environment/culture.
- **Recent jobs** shows your latest QA Tester jobs (queued / running / done) and refreshes while any are running.
  Finished ones get *Open report*. *Open QA Tester* opens the full tool.

## Adding more tools
The popup is organised into tool cards (`<section class="card">` in popup.html) under a shared
header and on/off switch. Add a new card there, and its logic alongside the existing code.
Storage keys (`ignoreRules`, `showIgnored`, `enabled`) are unchanged from the original build, so
existing settings carry over.
